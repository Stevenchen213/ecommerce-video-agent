> 代码目录：`脚本驱动双平台视频组装/video_pipeline/`

## 一句话目标

输入**结构化脚本** → **两步分类**（飞影/蝉镜 → 产品连续段）→ 各自生成**必用素材库** → 按脚本顺序 **FFmpeg 组装成片**。

当前阶段：框架可跑通（含 mock 生成）；两套真实 API **先占位、暂不深入改造**。

---

## 与旧素材库的区别

| | 旧做法 | 本框架 |
|--|--------|--------|
| 来源 | 外部杂库再选取 | 按脚本严格生成 |
| 每条视频 | 可能用不上 | **默认全部进成片** |
| 剪辑 | 挑选 + 找逻辑 | 按 shot 顺序组装 |

---

## 平台分工（可配置）

| Provider | 默认职责 | 说明 |
|----------|----------|------|
| **飞影数字人** (`feiying`) | 主播 / 数字人镜头 | API 占位，后续填真实调用 |
| **蝉镜** (`chanjing`) | 产品镜头（钩子、特写、掰开等） | 对接 FrameVideo Skill / 蝉镜 API，先占位 |

若实际职责对调，改配置即可，不必改组装主流程。

---

## 流水线

```text
脚本 Script
  → Schema 校验
  → Planner 两步分类（平台分流 → 产品连续段）
  → FeiyingProvider 单镜 / ChanjingProvider 按段连贯生成
  → 写入 library/{platform}/{shot_id}.mp4
  → 任务状态落盘（JSON）
  → Assembler：统一规格 → 按脚本顺序 concat
  →（可选）叠品牌资产（logo/BGM）
  → output/final.mp4
```

---

## 框架模块

1. **脚本 Schema + 校验** — `id / role / platform / 文案 / 时长` 等  
2. **Planner** — 两步分类：平台分流 + 相邻产品镜聚成连续段  
3. **Providers** — 飞影单镜 / 蝉镜按段（`generate_segment`），现为 mock  
4. **镜头素材库** — `library/feiying/`、`library/chanjing/`，键为 `shot_id`  
5. **任务状态表** — `jobs/state.json`（pending/running/done/failed）  
6. **Assembler** — FFmpeg 探测、对齐、顺序拼接  
7. **Storage 接口** — 本地实现；预留 OSS/S3  
8. **品牌资产库** — `assets/brand/`（logo、BGM、片尾，非生成）  
9. **配置** — `.env` / `config.example.env`
